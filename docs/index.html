§ 1

Cosa fa

Bozze da Markdown

Titoli, grassetto, corsivo, liste annidate, citazioni, codice e link diventano il corpo di una bozza online. Quello che non supporta (HTML grezzo, tabelle) lo rifiuta con un errore, senza perdere testo in silenzio.

Coda di note

Le note vivono in locale come bozze. Le pubblichi a mano o le programmi con un orario: notes run-due pensa al resto. Una nota dall'esito incerto non viene mai ripubblicata.

Generazione opzionale

Anthropic oppure qualunque server compatibile OpenAI (llama.cpp, Ollama, vLLM, LM Studio). Il testo generato diventa solo una bozza o una nota in coda: non pubblica mai nulla.

Su una macchina dedicata

Un'immagine Docker, i manifest per k3s (CronJob, PVC, Secret) e un timer systemd. Tre sole dipendenze di runtime: marked, yaml, zod.

§ 2

Regole di redazione

Il progetto è nato con una domanda: come impedire che uno script pubblichi, o mandi un'email a tutti gli iscritti, quando non doveva? Le risposte:

  • Pubblicare e programmare richiedono --yes quando non c'è un terminale, oppure una parola digitata a mano. Senza terminale il controllo avviene prima di qualsiasi richiesta di rete.
  • L'email agli iscritti parte solo con --send-email. Di default non si invia nulla.
  • Il cookie di sessione non finisce mai in output, log, file di dati o messaggi d'errore, e viene inviato solo a host substack.com. La chiave Anthropic va solo ad api.anthropic.com.
  • Link e immagini solo con schemi sicuri (http, https, mailto); niente HTML grezzo; caratteri invisibili e di controllo rifiutati.
  • Nessuna doppia pubblicazione: la coda delle note è protetta da un lock, e una nota di cui non si sa se sia uscita resta ferma finché non decidi tu.

§ 4

Stato: cosa è provato davvero

Substack non ha un'API pubblica: il CLI usa quelle interne, non documentate, che possono cambiare senza preavviso. Per questo ogni voce dice con onestà quanto è verificata.

Confermato

Su Substack reale

Lettura del profilo, elenco e lettura delle bozze, creazione di una bozza e nomi dei nodi del corpo (titoli, liste, citazioni, codice, link).

Collaudato

Docker e k3s

Immagine costruita, CronJob eseguito ogni minuto, pod non-root con filesystem in sola lettura, dati persistenti, errori di cookie visibili come Job falliti. Su un k3s a nodo singolo in WSL2.

§ 5

Avvio rapido

  1. Installa e compila

    git clone https://github.com/fullo/substack-cli.git
cd substack-cli
npm ci
npm run build

    Serve Node 22.18 o successivo.

  2. Configura la pubblicazione

    node dist/cli/main.js config init --publication la-tua-newsletter

    È la parte prima di .substack.com.

  3. Dai al CLI il cookie di sessione

    node dist/cli/main.js auth guide    # istruzioni passo passo
node dist/cli/main.js auth set      # il valore non viene mostrato
node dist/cli/main.js auth check

    Il cookie è come una password: chi lo ha agisce come te. Non incollarlo in chat o in file versionati.

  4. Crea una bozza

    node dist/cli/main.js article draft post.md --dry-run   # prova senza inviare
node dist/cli/main.js article draft post.md

    Il file inizia con un front-matter title: (e, se vuoi, subtitle:).
