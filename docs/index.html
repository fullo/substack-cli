§ 1

Il prodotto

Substack CLI è un programma da riga di comando che porta la scrittura di una newsletter fuori dal browser: scrivi in Markdown con il tuo editor, il CLI crea la bozza online, tu la rivedi nell'editor di Substack e la pubblichi quando decidi. Le note brevi vivono in una coda locale e partono a mano o a orario.

Bozze da Markdown

Titoli, grassetto, corsivo, liste annidate, citazioni, codice e link diventano il corpo di una bozza online. Quello che non supporta (HTML grezzo, tabelle) lo rifiuta con un errore, senza perdere testo in silenzio.

Coda di note

Le note vivono in locale come bozze. Le pubblichi a mano o le programmi con un orario: notes run-due pensa al resto. Una nota dall'esito incerto non viene mai ripubblicata.

Generazione opzionale

Anthropic oppure qualunque server compatibile OpenAI (llama.cpp, Ollama, vLLM, LM Studio). Il testo generato diventa solo una bozza o una nota in coda: non pubblica mai nulla.

Su una macchina dedicata

Un'immagine Docker, i manifest per k3s (CronJob, PVC, Secret) e un timer systemd. Tre sole dipendenze di runtime: marked, yaml, zod.

§ 2

Come si usa

  1. Installa e compila

    git clone https://github.com/fullo/substack-cli.git
cd substack-cli
npm ci
npm run build

    Serve Node 22.18 o successivo. Il comando è node dist/cli/main.js; negli esempi sotto lo abbreviamo in substack (con npm i -g . diventa un comando vero).

  2. Configura la pubblicazione

    substack config init --publication la-tua-newsletter

    È la parte prima di .substack.com. Con substack config show vedi la configurazione effettiva.

  3. Dai al CLI il cookie di sessione

    substack auth guide    # istruzioni passo passo
substack auth set      # il valore non viene mostrato
substack auth check    # verifica che la sessione sia valida

    Substack non ha API key: il CLI usa il cookie substack.sid del tuo account. Trattalo come una password e non incollarlo in chat o in file versionati. In alternativa puoi passarlo con la variabile SUBSTACK_SID.

  4. Scrivi e crea una bozza

    ---
title: Il titolo dell'articolo
subtitle: Un sottotitolo, se ti serve
---

## Un titolo di sezione

Testo con **grassetto**, *corsivo* e un [link](https://example.com).

- una lista
- con due voci
    substack article draft post.md --dry-run   # prova, senza inviare nulla
substack article draft post.md             # crea la bozza online
substack article list                      # elenca le bozze

    Il file inizia con un front-matter: title è obbligatorio, subtitle facoltativo. Puoi anche passare il testo da un altro programma con cat post.md | substack article draft -.

  5. Pubblica, con una conferma

    substack article publish 123456789
# Scrivi "pubblica" per confermare:

substack article publish 123456789 --yes                 # da script
substack article publish 123456789 --yes --send-email    # anche l'email agli iscritti

    Da terminale ti viene chiesta una conferma digitata; da uno script serve --yes, altrimenti il comando si ferma subito. L'email agli iscritti parte solo con --send-email.

  6. Note: coda locale, a mano o a orario

    substack note add "Una nota breve con un [link](https://example.com)"
substack note list --status draft
substack note schedule a1b2c3d4e5f6 --at 2026-10-09T09:00:00+02:00
substack note publish a1b2c3d4e5f6        # subito, a mano
substack note unschedule a1b2c3d4e5f6     # torna in bozza

    Le date vogliono sempre il fuso: +02:00 oppure Z per UTC. A orario le note vengono pubblicate da substack notes run-due, pensato per girare ogni minuto (vedi «Su una macchina sempre accesa»).

  7. Fatti aiutare da un LLM (facoltativo)

    # con un server locale, per esempio llama.cpp
llama-server -m modello.gguf --port 8080
substack config init --publication la-tua-newsletter --force \
    --provider openai-compat --llm-base-url http://localhost:8080 --model locale

substack generate article --topic "Cos'è il green coding" --draft
substack generate note --topic "Un consiglio sul green coding"

    Con --provider anthropic si usa invece l'API di Anthropic con la variabile ANTHROPIC_API_KEY. L'articolo generato viene salvato in locale e, con --draft, diventa una bozza online; la nota va nella coda. Non viene pubblicato niente.

  8. Su una macchina sempre accesa

    docker build -f deploy/Dockerfile -t substack-cli:0.1.0 .
docker save substack-cli:0.1.0 | sudo k3s ctr images import -

kubectl apply -f deploy/k3s/namespace.yaml -f deploy/k3s/pvc.yaml
read -rs SID && kubectl -n substack create secret generic substack-secrets \
    --from-literal=SUBSTACK_SID="$SID"; unset SID
# in deploy/k3s/configmap.yaml sostituisci SOSTITUISCI-SUBDOMAIN con il tuo
kubectl apply -f deploy/k3s/configmap.yaml -f deploy/k3s/cronjob.yaml

    Il CronJob esegue notes run-due ogni minuto. In alternativa, su una VM Linux, usa il timer systemd in deploy/systemd. Quando il cookie scade il comando esce con codice 2 e il Job risulta fallito, così te ne accorgi.

Riferimento dei comandi

auth guide · set · check · loginOttieni, salva e verifica il cookie (login apre un browser, con Playwright installato a parte).
config init · showCrea e mostra la configurazione.
article draft <file|->Crea una bozza da Markdown. --dry-run per provare.
article listElenca le bozze più recenti.
article publish <id>Pubblica una bozza. --yes, --send-email, --dry-run.
note add <testo|->Aggiunge una nota alla coda locale.
note list · schedule · unscheduleElenca (--status), programma (--at) o rimette in bozza.
note publish · resolvePubblica subito; resolve --published|--retry chiude una nota rimasta in dubbio.
notes run-duePubblica le note programmate scadute (cron, systemd, k3s).
generate article · noteGenera il testo con un LLM (--topic, --lang, --provider, --draft).

Quasi tutti i comandi accettano --json per un output leggibile da altri programmi.

§ 3

Casi d'uso

Quattro modi di usarlo, dal più semplice al più automatico.

Dall'editor alla bozza

Scrivi l'articolo come file Markdown, magari in un repository Git insieme agli altri. Quando è pronto lo mandi a Substack e lo rivedi nel loro editor.

substack article draft post.md --dry-run
substack article draft post.md
# apri il link, rivedi, poi:
substack article publish 123456789

Scrivere con un assistente

Il testo lo prepara un assistente (per esempio un assistente di codice nel terminale) e il CLI lo trasforma in bozza passandolo da stdin. Tu decidi se e quando pubblicare.

cat bozza-dell-assistente.md | substack article draft -

Note programmate per la settimana

Prepari in una volta le note e fissi gli orari. Un timer sulla tua macchina le pubblica al momento giusto; se qualcosa va storto (cookie scaduto, Substack che non risponde) lo vedi come errore, e una nota dubbia non viene mai ripubblicata.

substack note add "Lunedì: nuova puntata online"
substack note schedule a1b2c3d4e5f6 --at 2026-10-12T09:00:00+02:00
substack notes run-due        # ogni minuto, da cron

Prima stesura con un modello locale

Un modello che gira sul tuo computer (llama.cpp, Ollama…) scrive una prima stesura sul tema che indichi. Il risultato diventa una bozza online da rifinire: niente esce senza la tua revisione.

substack generate article \
    --topic "Cos'è il green coding" --draft
§ 4

Regole di redazione

Il progetto è nato con una domanda: come impedire che uno script pubblichi, o mandi un'email a tutti gli iscritti, quando non doveva? Le risposte:

  • Pubblicare richiede --yes quando non c'è un terminale, oppure una parola digitata a mano. Senza terminale il controllo avviene prima di qualsiasi richiesta di rete.
  • L'email agli iscritti parte solo con --send-email. Di default non si invia nulla.
  • Il cookie di sessione non finisce mai in output, log, file di dati o messaggi d'errore, e viene inviato solo a host substack.com. La chiave Anthropic va solo ad api.anthropic.com.
  • Link e immagini solo con schemi sicuri (http, https, mailto); niente HTML grezzo; caratteri invisibili e di controllo rifiutati.
  • Nessuna doppia pubblicazione: la coda delle note è protetta da un lock, e una nota di cui non si sa se sia uscita resta ferma finché non decidi tu.
